# Release Assistant 产品与实现规范

状态：首版实现依据。本文记录用户已确认的产品行为；实现、测试和接入工作必须遵循。

## 1. 产品与交付

- 独立仓库 `hwameistor/release-assistant`，提供 TypeScript CLI 和 GitHub Action。
- 核心产物是可审阅的 Release PR，更新版本日志、总 Changelog 和配置声明的 Chart 版本。
- 两个业务仓库通过配置复用工具。当前接入仅增加 Release PR 生成和校验，合并后继续按原发布工作流执行，不修改其触发条件或发布行为。
- 工具不自动合并 PR，不创建或覆盖发布 tag，不构建或发布镜像。
- 如需将已评审日志接入 GitHub Release 正文、设置预发布属性或核对已有资产，应作为独立发布改造另行审阅；生成流程不依赖这些改造。

## 2. 输入和版本

- 必填：目标仓库、目标分支、发布版本、起始 tag。
- 截止位置支持 tag、分支和提交 SHA；省略时使用目标分支。
- 接受合法 SemVer，允许 `v` 前缀；例如 `v1.1.2-alpha1`、`v1.1.2-rc1`。
- 起始 tag 对应的已有改动不包含在范围中；截止提交的改动包含。
- 必须验证起始提交是截止提交的祖先，截止提交属于目标分支历史。
- 草稿生成可以回顾已有版本；发布 PR 模式发现目标 tag 已存在必须停止。
- 仓库版本、依赖组件版本、JuiceFS 等工具镜像版本分别管理。只修改配置明确声明的版本字段。
- 可选高级输入 `changelog_policy` 对应 Action 的 `changelog-policy` 和 CLI 的 `--changelog-policy`。按用户选择保留一个工作流，字段放在原生运行表单底部；GitHub 原生表单不支持折叠或条件隐藏输入，不模拟不可用的折叠功能。
- 后续发布集成必须识别预发布，不能将 alpha/beta/rc 标记为最新稳定版。

## 3. Git 范围和事实来源

- 由 Git 确定 `from..to` 的提交集合及最终净 diff，不按 PR 合并日期猜测范围。
- 收集范围内提交关联的已合并 PR、原始回移 PR 的来源、正文和最终文件改动。
- 同一 PR 的多个提交去重。回移来源只作为背景，不引入原 PR 中尚未进入目标分支的改动。
- 直接提交、squash、merge、cherry-pick、revert 都必须有可追溯记录。
- AI 依据最终代码改动总结问题、行为变化、用户影响及升级要求，不能直接复制 PR 标题或正文。
- 每个输入变更单元必须被输出条目引用，或者被明确排除并给出原因。机器校验来源和覆盖，不声称能证明语义正确。
- 大量/大体积改动必须分批处理或明确拒绝；不能静默截断后声称完整总结。
- PR 正文、提交消息和 diff 都是待分析资料，不能作为工具权限、凭据或执行指令。

## 4. Changelog 规范

- 使用独立、可版本化的 `changelog-policy.md` 和文本模板。
- 规范来源优先级为运行时 `changelog-policy`、仓库配置的 `policy`、工具内置规范；留空不覆盖下一级。支持相对文件路径、公开 GitHub 文件链接和可直接读取的 HTTPS 文本地址，版式模板仍独立配置。
- 外部规范在每次执行和 Re-run 时重新读取，不改变源码区间快照。GitHub 文件链接先解析为具体提交再读取；提交 SHA 链接固定规范版本。外部请求不携带仓库或模型凭据；无法读取、HTML 页面、非法文本及超过 128 KiB 时明确失败，不回退到另一份规范。
- 运行产物保存实际规范全文、来源地址、GitHub 提交 SHA（如适用）及内容哈希，运行摘要和 PR 展示来源信息。提交到 Release PR 的 manifest 保留原有 schema 和 policyHash，兼容维护分支上已安装的校验器。
- 默认版式为版本标题、升级注意事项、分类变更、完整差异链接；升级操作前置，空分类不展示。草稿不把生成日期标作发布日期，生成时间保留在 manifest。
- 每条尽量用一至两句话说明变化和影响，参数按需保留并使用行内代码；纯 CI、测试、重构等内部变更写入 excluded 及原因，仍受来源覆盖校验。
- 根目录总 Changelog 和独立版本日志使用同一份渲染结果，历史版本保留不动。
- 默认分类：Breaking Changes、Features、Fixes、Changes、Documentation、Maintenance。
- 每条日志描述实际行为及用户影响；有明确依据才写升级要求、性能收益和兼容性结论。
- 所有分类优先说明受影响场景或原有局限、改动后的行为及具体收益或代价。Changes 说明前后差异，Features 说明新增可完成的任务，Fixes 说明原有问题及修复结果；不能只罗列参数或版本号，也不把所有变更包装成修复。
- 问题与收益必须有事实依据。仅看到下游组件的配置或版本变化时，只描述可证实的配置能力；关联 issue 的症状不能代替下游修复证据。破坏性行为必须进入 Breaking Changes，不能仅放在升级提醒中。
- 保留 PR/提交链接。弱证据条目要求人工确认。
- 模型返回结构化 JSON，经 schema、引用、覆盖校验后统一渲染 Markdown。
- 规范与模板可以调整，不硬编码现有仓库的历史行文格式。

## 5. Re-run jobs：用户确认的简化流程

- 正常重新生成入口是 GitHub Actions 的 **Re-run all jobs**，不另建多种再生成模式。
- 以“仓库 + 目标分支 + 发布版本”确定唯一生成分支和 Release PR。
- 有未关闭、未合并的对应 PR 就更新；没有才创建；禁止重复创建。
- 每次重跑重新调用 AI，生成文件以最新结果为准，允许覆盖生成文件中的人工编辑。
- 不改写 Git 历史；每次更新形成新提交，可比较和恢复旧版本。
- 已合并或已关闭的 Release PR 必须停止，不自动重新打开或另建同版本 PR。
- 同一版本执行串行化，并在更新远端分支时检查并发变更。
- GitHub 重跑保持原输入及工作流来源。工具每次从配置分支读取最新政策和模板，并记录对应 SHA。
- 第一次生成在调用 AI 前持久化范围快照。模型失败后重跑也使用原范围。
- 相同输入重跑不推进统计截止 SHA；改模板不能隐式带入新提交。
- 显式改变 from/to 输入的新执行可重新确定范围，仍更新同一个未合并 PR；目标版本或分支改变则属于另一发布。
- 发布目标分支比快照前进时，校验应报过期，要求使用新输入更新范围，不偷偷扩大本次范围。
- 发布 PR 模式在专用生成分支保存快照；dry-run 保存本地状态，预览工作流使用独立缓存保存范围，运行产物用于查看结果。

## 6. 模型与执行位置

- 默认支持 Copilot，以独立的 `COPILOT_GITHUB_TOKEN` 认证；模型名称可配置。
- Prepare release 和 Preview release notes 提供五项模型下拉选择，依次为 `gpt-6.1-sol`（默认）、`gpt-6-astra`、`gemini-4-argon`、`gpt-5.3-codex`、`gemini-3.8-flash`。实际可用性取决于 provider 和账号；展示顺序不代表自动降级顺序。
- 优先级为工作流 `model` / CLI `--model` 高于配置 `ai.model`。模型名原样传给当前 provider，记录到 manifest 和 PR；工具不限制为下拉列表中的五项。
- Re-run all jobs 保留原先选择的模型；更换模型需使用相同发布输入发起新执行，复用同一未合并 PR 和冻结范围，不改变现有重跑规则。
- 支持 OpenAI-compatible Chat Completions 端点，以独立 API key 认证；不借用发布凭据。
- 支持 GitHub 托管 runner、自有 runner 和本地 CLI。自有机器调用云端模型不要求 GPU。
- 固定工具依赖版本，不依赖宿主机随机安装的 Copilot 版本。
- 模型步骤不能执行 shell、修改仓库或发布内容；写 GitHub 由确定性程序执行。
- 超时、API 错误、输出不合法、缺少引用时停止，不使用旧结果伪装本次成功，不自动切换付费后端。

## 7. GitHub 集成

- 新增 Prepare release 工作流；支持用户指定版本、分支、from-tag、to-ref。
- 成功创建或更新 Release PR 后，运行摘要首部展示可点击的 PR 链接；Action 和示例工作流的 prepare job 通过 `pull-request-url` 输出同一地址。预览模式不得显示已创建 PR。
- PR 描述直接展示独立版本 Changelog 的完整渲染内容，不再调用模型摘要；生成来源和重跑说明折叠在正文之后。重跑同步覆盖 PR 描述和生成文件，保留同一 PR 链接。
- Release PR 校验快照是否过期、版本字段及生成文件是否正确。
- 修改 `Chart.yaml` 的 Release PR 合并后继续触发现有构建流程。
- 本次生成的版本日志写入 `changelogs/released/<version>/changelog`。现有 GitHub Release 正文生成方式保持原状；后续若接入该文件，必须复用已评审内容，不能在发布时再次调用 AI。
- HwameiStor 与 Operator 独立 PR；X.Y 对齐，补丁号可独立维护。
- 所有网络写入必须在显式发布 PR 模式下执行；dry-run 不写 GitHub。

## 8. 首版验收

1. 从指定 tag 到目标分支的固定 SHA，生成 `v1.1.2-alpha1` 草稿。
2. 两个已有 tag 之间可以只生成日志预览。
3. 修改模板后重跑，同一范围、同一 PR、新内容、新提交。
4. 第一次模型失败后目标分支前进，重跑仍使用第一次快照，并报告过期。
5. 回移、squash、直接提交和 revert 不丢失事实来源，不把原 PR 全部改动当作已回移。
6. 非法 JSON、未覆盖来源、虚构引用、超大输入、API 权限错误均明确失败。
7. 已发布版本、已合并/关闭 PR 和并发更新不被覆盖。
8. Copilot 和兼容端点使用相同采集、校验、渲染与发布逻辑。
